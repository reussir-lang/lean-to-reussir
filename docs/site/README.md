# lean2rr design site

A static HTML site that explains lean2rr's architecture and design with
diagrams. Open [`index.html`](index.html) in a browser, directly from a
clone (`file://`). The site needs no network, no CDN and no JavaScript.

The site summarizes. The markdown documents in the repository
(`docs/translation-plan.md`, `docs/implementation/`, `runtime/README.md`,
`tests/README.md`) are the authority, and the pages link to them.

The site describes lean2rr and the Reussir code that it generates. It does
not describe the local Reussir patches, Reussir's bugs and other issues,
the patch series, the Reussir commit or branch that the builds use, or
lean2rr's workarounds for Reussir bugs. That material stays in
`reussir-bugs/` and `docs/implementation/reussir-workarounds/`. A rule of
lean2rr that exists because of a Reussir issue stays on the site, without
the reference to the issue.

## Files

| File | What it is |
|---|---|
| `pages/*.md` | The page texts (Markdown with placeholders). Edit these for prose. |
| `diagrams.py` | The diagrams, as Python functions that write inline SVG. |
| `build.py` | Builds every page: fills the placeholders, converts Markdown, writes `*.html`. |
| `style.css` | The style, light and dark. |
| `*.html` | Generated by `build.py` and committed, so that a clone can open them. Do not edit them by hand. |

## Rebuild

From the repository's root:

```
python3 docs/site/build.py           # write the pages
python3 docs/site/build.py --check   # write nothing; fail if a page is out of date
```

`build.py` needs Python 3 and the `markdown` module only. The output
depends only on the repository's files: not on the date, the commit or the
machine. So building twice gives the same pages, and `--check` passes
right after a build.

Run `build.py` and commit the pages whenever a change touches what the site
shows: a source it reads (below), a page, a diagram or the style.
`--check` tells whether the committed pages are up to date.

## Placeholders in pages/*.md

| Placeholder | Filled with |
|---|---|
| `{{svg:NAME}}` | the diagram `NAME` of `diagrams.DIAGRAMS` |
| `{{gen:NAME}}` | a table that `build.py` generates from the repository (`GENERATORS`) |
| `{{v:NAME}}` | a short value: the Lean version, counts (`values()`) |
| a link target `repo:PATH` (in a Markdown link or an `href`) | a relative link to `PATH` in the repository |

What is generated, and from where:

| Generated part | Source |
|---|---|
| the pass table, the required parts, the Stage 2 edits | `lean2rr/LeanToReussir/Opt/Registry.lean`; the guards from `docs/implementation/optional-passes.md` |
| test counts, `.xfail` tests, loader checks | `tests/runtime/`, `tests/env/run.sh`, `tests/classic/cases.json`; the `#[test]`s of `runtime/leanrt/src` |
| the classic corpus table | the "Cases" table of `tests/README.md` |
| the index of known differences | the groups and items of plan §10 |
| "Lean bugs we do not reproduce" | the items of plan §10's group of that name, when it exists |

## Checks

`build.py` stops, and writes nothing, when the site's sources or pages
contain a forbidden string: local paths, private notes, private projects
(the list is `FORBIDDEN` in `build.py`). The site is public.

It also compares the sources with each other and prints a warning for each
disagreement (`--check` fails on a warning):

- every pass of the registry is in `optional-passes.md` and in the pass
  table of `docs/implementation-status.md`, and the reverse;
- the runtime test count in `docs/implementation-status.md` matches
  `tests/runtime`.

## Keeping it up to date

- Change the markdown documents first, then the page that summarizes the
  change, then run `build.py`.
- Most counts and tables follow the sources. Hand-written results (the
  last full run, performance figures, the recent changes) carry their
  date in the text: update them when they change.
- Writing style: about 80% ASD-STE100 (Simplified Technical English).
  Short sentences (about 20 words for steps, 25 for descriptions), active
  voice, one idea per sentence, one term per concept (see the glossary
  page), simple words, lists and tables where they help. Technical names
  (LCNF, monomorphization, Reussir) are fine. Explain a Lean example line by
  line, with a Rust analogy. State decisions as the project's decisions.
- After a change to a diagram, check it in a browser. Text in SVG does not
  wrap: keep box labels short.
